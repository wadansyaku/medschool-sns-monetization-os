# Codex 運用手順

## 目的

Codex を `企画担当 + 台本担当 + 再利用担当 + 週次レビュー担当` として使い、このディレクトリだけで運用が回る状態を維持する。

## 基本ルール

- 依頼単位は常に `1テーマ1パッケージ`
- 最初に長尺、次に再利用、最後にレビューの順で進める
- 各媒体ごとに別テーマを発注しない
- 毎回、相談導線にしたい悩みを 1 つ明示する
- 医療助言や診断に見える表現は入れない

## 週次フロー

### 月曜: 企画

- 入力:
  - 先週の数値
  - DM で多かった悩み
  - 今週の仮テーマ
- 使うファイル:
  - `01_strategy/strategy_hub.md`
  - `03_analytics_os/post_log.csv`
  - `03_analytics_os/weekly_review.md`
- 使うプロンプト:
  - `04_codex_os/codex_prompts.md` の「週初企画」
- 出力先:
  - 新しい週次パッケージを `02_content_os/packages/` に作る

### 火曜: 長尺台本

- 入力:
  - 核テーマ
  - 想定視聴者
  - 今週扱いたい悩み
- 使うプロンプト:
  - `04_codex_os/codex_prompts.md` の「長尺台本生成」
- 出力:
  - タイトル
  - 章立て
  - CTA
  - テロップ案

### 水曜から木曜: 再利用

- 入力:
  - 長尺台本または長尺の要点
  - 切り出したい論点
- 使うプロンプト:
  - `04_codex_os/codex_prompts.md` の「再利用生成」
- 出力:
  - 短尺 4 本
  - カルーセル 1 本
  - X 投稿 10 本以上

### 日曜: レビュー

- 入力:
  - `03_analytics_os/post_log.csv`
  - 今週の DM メモ
  - 公開した投稿一覧
- 使うプロンプト:
  - `04_codex_os/codex_prompts.md` の「週末レビュー」
- 出力:
  - 勝ちパターン
  - 負けパターン
  - 次週の核テーマ候補
  - CTA 改善案

## Codex に渡す最小コンテキスト

- 誰に向けた発信か:
  - 医学部受験生
- どの立場で発信するか:
  - 医学生
- 何を売るか:
  - 単発の個別相談
- 何を避けるか:
  - 医療助言
- 今週の核テーマ:
  - 1つだけ

## 推奨ワークフロー

1. `strategy_hub.md` を開いてブレを防ぐ
2. 週初企画プロンプトで核テーマを確定する
3. 長尺台本生成プロンプトで YouTube を先に作る
4. 再利用生成プロンプトで短尺・カルーセル・Xへ分解する
5. 必要なら `external_review_loop.md` に沿って Atlas へ方向性レビューを依頼する
6. 投稿後の結果を `post_log.csv` に入力する
7. 週末レビューで翌週テーマへ反映する

## 命名ルール

- 週次パッケージ:
  - `week_XX_topic_slug.md`
- 投稿 ID:
  - `PLATFORM-WXX-TYPE-INDEX`
- 相談導線:
  - 全媒体で同じ文言を使う

## 迷った時の優先順位

1. 相談化しやすい悩みを優先する
2. 保存されやすい整理型コンテンツを優先する
3. バズ狙いより、再利用しやすい構造を優先する
4. 新しい企画より、勝ち筋の深掘りを優先する

## GitHub / Atlas 補助ルール

- GitHub の差分単位は、常に `1テーマ1パッケージ`
- Atlas には、完成品全部ではなく `核テーマ・CTA・伸び悩みの原因` を優先して聞く
- Atlas や PR で出た指摘は、`03_analytics_os/advice_log.md` に必ず残す
- 外部の助言を採用する時は、次週で何を検証するかまで決める
